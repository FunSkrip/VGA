# Отчёт по схеме аудита VGA

**Проект:** Video Segmentation Analytics (VGA)  
**Схема БД:** Alembic `d11a1bda453d`  
**Дата:** 27.11.2026

## 1. Назначение

Аудит фиксирует действия пользователей, администраторов и служебных процессов, связанные с безопасностью и обработкой данных.

Основной поток:

```text
Пользователь → HTTPS/reverse proxy → Flask → выполнение операции
             → audit_event() → SQLite audit_log → защищённое хранилище
```

## 2. Что сохраняется в журнале

Каждая запись содержит:

- время события в UTC;
- ID и имя пользователя;
- `request_id`;
- действие;
- тип и ID объекта;
- IP-адрес;
- User-Agent;
- структурированные детали в JSON.

Пароли, `SECRET_KEY`, `GEMINI_API_KEY`, содержимое медиафайлов и полный текст вопросов чат-бота в журнал не записываются.

## 3. Основные события

| Группа | События |
|---|---|
| Учётные записи | регистрация, успешный/неуспешный вход, выход, смена роли, блокировка |
| Доступ | отказ в доступе к маршруту, отказ к чужому медиафайлу |
| Загрузка | принятая загрузка, `upload_rejected` с причиной |
| Детекция | старт, завершение, ошибка, `duration_seconds` |
| Медиа | просмотр, скачивание, удаление |
| Чат-бот | запрос, ответ, ошибка Gemini, превышение лимита, circuit breaker |
| Модели YOLO | проверка, включение/выключение, скачивание и ошибки |
| Служебные | backup, restore, экспорт аудита |

## 4. Защита и доступ

- журнал хранится в SQLite на шифрованном BitLocker-томе;
- доступ к странице аудита — только `admin` и `auditor`;
- аудитор работает в режиме только чтения;
- редактирование и удаление записей через интерфейс отсутствуют;
- экспорт CSV/JSON с учётом фильтров и лимитом 10 000 событий;
- экспорт также фиксируется событием `audit_exported`;
- `request_id` берётся из `X-Request-ID` или генерируется приложением.

## 5. Что проверено

- 180 событий в журнале;
- 35 автоматических тестов проходят;
- проверены вход, роли, медиа, детекция, чат-бот, backup/restore и экспорт;
- реальная загрузка JPEG: `detection_completed` содержит `duration_seconds`;
- отклонённый файл `.exe`: создаётся `upload_rejected`;
- проверка модели: создаётся `model_verified` с SHA-256 и размером;
- backup и restore проверены на копии БД.

## 6. Ограничения

- HMAC-цепочка для защиты журнала от подмены не используется — по решению проекта.
- Rate limiting для `login`/`register`/`upload` выполняется на уровне nginx; отказы по этим лимитам остаются в логах proxy, а не в `audit_log`.
- Для чат-бота отказы по лимиту фиксируются в аудите.

## 7. Вывод

Основная схема аудита из ЛР №2 реализована: события безопасности и обработки данных фиксируются, журнал структурирован, доступ разграничен, экспорт и `request_id` работают. Защита от подмены журнала ограничена правами ОС, BitLocker и отсутствием редактирования через интерфейс.
